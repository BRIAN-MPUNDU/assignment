# ICT251 Activity 4 — CampusPulse School Event Noticeboard

A colorful, responsive single-table CRUD application built with Node.js, Express, SQLite, HTML, CSS and vanilla JavaScript. It follows Question 12 in the assignment: **School Event Noticeboard** (`notices` resource/table).

## 1. Features

- One SQLite table named `notices` with an auto-incrementing integer primary key, six required theme fields, status, and timestamps.
- Ten sample campus notices inserted automatically on first startup.
- REST API: list all, get one, create, update, and delete.
- JSON responses for API success and errors; input validation and not-found handling.
- CORS enabled.
- Colorful responsive frontend with create/edit/delete, search, status filtering, dashboard counts, and refresh.
- Postman collection with all five required endpoints and automated checks.

## 2. Database design

Only one application table is created: `notices`.

| Field | Type | Purpose |
|---|---|---|
| `id` | INTEGER PRIMARY KEY AUTOINCREMENT | Unique record identifier |
| `event_title` | TEXT NOT NULL | Event name |
| `category` | TEXT NOT NULL | Academic, Social, Sports, etc. |
| `description` | TEXT NOT NULL | Event details |
| `venue` | TEXT NOT NULL | Location |
| `event_date` | TEXT NOT NULL | Event date in `YYYY-MM-DD` format |
| `organizer` | TEXT NOT NULL | Club, department or organiser |
| `status` | TEXT NOT NULL | Upcoming, Ongoing, Completed or Cancelled |
| `created_at` | TEXT | Creation timestamp, default current time |
| `updated_at` | TEXT | Last update timestamp, refreshed by PUT |

The assignment's general database requirement asks for at least five additional fields beyond `id`; this design provides seven content/status fields plus two timestamps. The table/resource name is `notices`, matching Question 12.

## 3. Software prerequisites

Install Node.js 18 or newer. Confirm in PowerShell:

```powershell
node --version
npm --version
```

No separate SQLite server is needed; SQLite stores data in a local database file.

## 4. Install and run (Windows PowerShell)

1. Extract the project ZIP to a folder you can find easily.
2. Open PowerShell in the extracted `ict251_noticeboard` folder.
3. Enter the backend directory and install packages:

```powershell
cd backend
npm install
```

4. The supplied `.env` file contains local settings. If needed, create it from `.env.example`. The settings are:

```env
PORT=3000
DB_PATH=./noticeboard.sqlite
```

5. Start the API and frontend:

```powershell
npm start
```

6. Open **http://localhost:3000** in your browser. The app initializes `noticeboard.sqlite`, creates the table, and inserts ten sample notices when the table is empty.
7. API health check: **http://localhost:3000/api/health**.
8. All notices: **http://localhost:3000/api/notices**.

Keep the terminal open while using the app. Stop the server with `Ctrl+C`.

## 5. Required REST API endpoints

Base URL: `http://localhost:3000`

| Method | Endpoint | Expected success |
|---|---|---|
| GET | `/api/notices` | `200 OK`, JSON array and count |
| GET | `/api/notices/:id` | `200 OK`, one JSON record |
| POST | `/api/notices` | `201 Created`, new record |
| PUT | `/api/notices/:id` | `200 OK`, updated record |
| DELETE | `/api/notices/:id` | `200 OK`, deletion confirmation |

The `:id` placeholder must be replaced by a real numeric notice ID. POST and PUT require a JSON body containing `event_title`, `category`, `description`, `venue`, `event_date`, and `organizer`; `status` is optional and defaults to `Upcoming`.

Example JSON request body:

```json
{
  "event_title": "Student Innovation Day",
  "category": "Academic",
  "description": "Students demonstrate creative projects.",
  "venue": "Main Hall",
  "event_date": "2026-11-20",
  "organizer": "Computer Science Department",
  "status": "Upcoming"
}
```

## 9. Deployment and submission notes

The assignment asks for a cloud deployment, shared API links, and a Google Form submission. Those external actions require your own hosting account and the actual class Google Form link, so they are not completed by this local project ZIP.

For a Node/Express deployment, use a Node-capable host and configure `PORT` through its environment. **Important:** SQLite needs persistent disk storage on many cloud hosts; ephemeral filesystems can erase the database on redeploy/restart. Configure a persistent disk and set `DB_PATH` to a path on that disk, or use a database service approved by your lecturer. If the lecturer specifically requires Firebase/Supabase/FastAPI rather than the SQLite design in the opening brief, ask which conflicting instruction takes precedence before changing the backend/database technology.

After deployment, change the Postman `baseUrl` collection variable to your deployed API origin. If hosting frontend separately, set `API_BASE` near the top of `frontend/app.js` to the deployed backend origin and keep CORS enabled. Submit the actual public URLs and the requested video/screenshots through your lecturer's Google Form; do not submit localhost URLs as public deployment links.

## 10. Troubleshooting

- **`npm` is not recognized:** install Node.js LTS, restart PowerShell, and verify `node --version` and `npm --version`.
- **Port 3000 is busy:** change `PORT=3001` in `.env`, restart, and open `http://localhost:3001`.
- **Cannot load notices:** check the terminal for errors and confirm the API health URL opens.
- **Native SQLite install fails:** use a current Node.js LTS release and rerun `npm install` from `backend`.
- **Database needs a reset for demonstration:** stop the server, back up any data you need, delete `backend/noticeboard.sqlite`, and restart. The schema and ten demo rows will be recreated.
